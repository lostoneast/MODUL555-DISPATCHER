# Контроллеры и маршруты

Каждый ресурс имеет собственный контроллер в `Controllers/Catalogs`: изделия,
типы изделий, заводы, линии, возможности линий, объекты строительства, секции,
этажи, такты, точки разгрузки, склады, перевозчики, типы ТС, транспорт и маршруты.
Контроллеры принимают DTO через стандартный model binding; бизнес-операции,
проверки и запросы EF Core выполняет `CatalogService`.
`AdminService` обслуживает обзор, роли и аудит, `DemoDataService` — демо-данные.
Контроллеры не зависят от `DispatcherDbContext`.

## API

Для каждого ресурса сохранён адрес `/api/<resource>`:

- `GET /` — список с пагинацией;
- `POST /` — создание;
- `PUT /{id}` — изменение, тип ключа соответствует ORM (`int` или `long`);
- `GET /lookups` — значения для выбора;
- `GET /export`, `POST /import` — Excel;
- `DELETE /{id}`, `POST /{id}/activate` — только для моделей с `IsActive`.

Исключение: DELETE объекта строительства теперь выполняет подтверждённое физическое
удаление зависимостей, а не деактивацию. Требуется тело с названием и токеном
предварительного расчёта. Правила сохранения физических изделий описаны в
[object-workspace.md](object-workspace.md).

Для секций, этажей, типов ТС, тактов и изделий маршруты деактивации отсутствуют:
у этих моделей нет `IsActive`. Старый `/api/lookups/{entity}` сохранён для клиентов.
Универсальных CRUD-маршрутов `/{entity}` больше нет.

`GET /api/construction-objects/{id:int}` возвращает объект независимо от страницы
списка и признака активности, включая фактическое количество секций, этажей и тактов.
При создании объекта можно передать `sectionsCount`, `floorsCount`, `autoAddFloors`
и `taktsCount`. Этажи создаются в каждой секции при `autoAddFloors=true`.
Такты создаются в статусе Draft с общим окном дат объекта; даты обязательны,
если запрошены такты. Весь граф сохраняется одним `SaveChangesAsync`.
Изменение объекта не перестраивает его секции, этажи и такты.

Ошибки отсутствующей записи возвращают 404, аргументов — 400, конфликты
уникальности, внешних ключей и конкурентного изменения — 409.
Авторизация существующих маршрутов сохранена.

## Веб-приложение

Канонический адрес изделий — `/products`, `/` перенаправляет на него.
`App.tsx` явно импортирует `pages/catalogs/index`, чтобы одноимённый старый
`pages/catalogs.tsx` не подменял новые страницы. Карточка объекта использует
запрос по ID. Список объектов поддерживает пагинацию и отображает данные ORM.
Закрытие формы `/construction-objects/new` возвращает к списку.

## Проверки

```text
dotnet build src/Modul555.Dispatcher.Api --no-restore
dotnet run --project tests/DispatcherApp.ContractChecks
cd web
npm run build
```

ContractChecks использует реальное обнаружение MVC-контроллеров и метаданные EF:
проверяет уникальность маршрутов, типы ключей, доступность операций и валидацию.
База данных и Keycloak для этих проверок не нужны; миграции и записи не выполняются.
