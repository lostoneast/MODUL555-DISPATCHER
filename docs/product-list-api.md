# Расширенный список изделий — серверный этап

`GET /api/products` сохраняет ответ `{ items, total, page, pageSize }` и прежние
поля изделия. Добавлены сведения о текущем назначении, такте, потребности,
производстве, складе, рейсе и идентификаторах. Интерфейс и редактирование
связанных сущностей на этом этапе не менялись. Старый Excel-экспорт пока не расширялся.

Правила выбора данных для одной строки:

- Текущее назначение на объект: открытое `ProductAssignment` с наиболее поздним
  `ValidFrom`, затем ID. При отсутствии используется проектная позиция.
- Такт: последнее открытое `TaktAssignment`.
- Дата потребности: ближайший `RequiredDeliveryDate` текущей версии незавершённой,
  неотменённой потребности. Дополнительно возвращаются окно производства, ранняя
  доставка, приоритет, ID потребности и её такта. `openDemandCount` учитывает также
  незавершённые потребности без текущей версии: дата у них пока отсутствует.
- Производство: последнее открытое неотменённое назначение среди текущих версий
  неотменённых потребностей. Оно может относиться к другой потребности, чем
  ближайшая дата доставки; `productionDemandRevisionId` явно указывает связь.
- Склад: последнее размещение без даты выбытия. `lastStorageDepartedAt` отдельно
  содержит последнюю дату выбытия из истории, а не дату выбытия с текущего склада.
- Рейс: последнее добавление в рейс, который не завершён и не отменён.
  `activeTripCount` позволяет заметить несколько назначений. Плановые и фактические
  даты относятся именно к выбранному рейсу.
- Идентификаторы: все идентификаторы изделия, включая неактивные, с типом,
  значением и датами назначения/отзыва.

Отсутствующие связи возвращаются как `null`. История назначений и рейсов не
размножает строки списка; она предназначена для будущей карточки изделия.

## Фильтры

`GET /api/products/fields` описывает все доступные поля, типы, допустимые операции,
возможность сортировки и значения enum. Названия полей соответствуют JSON, например
`mark`, `weightKg`, `requiredDeliveryDate`, `tripNumber`, `identifiers.value`.

Все фильтры объединяются через AND. Диапазон задаётся двумя фильтрами одного поля.
Текстовое сравнение без учёта регистра; даты — `yyyy-MM-dd`, время — ISO 8601
(без часового пояса считается UTC), дробные числа — с точкой.

```text
GET /api/products?page=1&pageSize=50&sortBy=requiredDeliveryDate&descending=false
  &filters[0].field=mark&filters[0].operator=Contains&filters[0].value=НС
  &filters[1].field=requiredDeliveryDate&filters[1].operator=Gte&filters[1].value=2026-09-01
  &filters[2].field=requiredDeliveryDate&filters[2].operator=Lte&filters[2].value=2026-09-30
  &filters[3].field=tripId&filters[3].operator=IsEmpty
```

Параметры примера передаются одной URL-строкой с обычным URL-кодированием.
Операции: `Eq`, `NotEq`, `Contains`, `Gte`, `Lte`, `IsEmpty`, `IsNotEmpty`.
Для чисел и дат доступны диапазоны, для текста — Contains, для enum и bool —
равенство/неравенство. IsEmpty означает null или пустую строку. Сравнения со
значением (включая NotEq) не включают отсутствующие значения.

Фильтры `identifiers.*` должны выполняться на одном и том же идентификаторе.
Например, тип QrCode, значение и isActive=true проверяются совместно. IsEmpty
для `identifiers.revokedAt` ищет существующий идентификатор без даты отзыва,
а не изделие без идентификаторов.

До 50 фильтров, 1–200 изделий на странице. Сортировка доступна по каждому
скалярному полю; ID изделия добавляется вторым ключом для стабильной пагинации.
Неизвестные поля, несовместимые операции и неверные значения дают HTTP 400.
Фильтрация, сортировка и пагинация выполняются в БД; идентификаторы загружаются
одним дополнительным запросом только для текущей страницы.
